# Getting Started

## Introduction

The HWaaS was designed out of a need for an easily extendable HIL test setup. It uses easily sourced components to create setups for teams to have shared access to hardware. It is tightly coupled to NixOS, to allow for maximum reproducibility amongst teams.

import Callout from "../../components/Callout.astro";

<Callout type="note">
  The HWaaS is not a one stop solution for all teams, but it will be of
  particular relevance if your team has some of the following requirements.
</Callout>

- Shared hardware leases amongst your team
- Need to boot machines under test with USB-Mass devices
- Interest in NixOS and reproducible test infrastructure
- Slowly expand your testing setup, machine by machine
- Manage networking, or auxiliary devices amongst machines
- Minimal KVM and serial interface for each machine
- Desire for memory safe, performant infrastructure
- Testing library for writing NixOS integration tests
- API and Web UI for managing reservations and interacting with machines

## Compare and Contrast

### LAVA

HWaaS is less concerned and opinionated with your test runs and packages. Since you are effectively creating CI/CD pipelines with your own images, services and hardware, you don't need to learn any additional tooling besides having your NixOS integration tests.

This is a double-edged sword. The HWaaS ispiece by piece less opinionated and offers fewer features, but we've found it to be very flexible for writing tests on real hardware.

Additionally, HWaaS's tight coupling with NixOS also helps enforce a level of reproducibility in your tests. You will be running the exact same supply chain, every time you run your application.

HWaaS is also designed around the development and debugging stages. Developers can lease machines, debug with the Web UI, script various tests and more.

---

### PiKVM

PiKVM is a lightweight KVM solution running on a Raspberry Pi, that allows you to perform remote hands debugging on individual machines.

The `remote-hands` services are capable of running on Raspberry Pi's or other SBCs, and they are somewhat architecturally similar to the PiKVM.

<Callout type="note">
  In fact, a strong mental model for the HWaaS is "What if I had NixOS control a
  number of PiKVMs, and could use this to manage shared hardware leases, network
  connectivity, and power switches."
</Callout>

Where the PiKVM allows you to control a single machine, the HWaaS provides a platform for reproducible testing and functionality around a fleet of devices.
You can control the networking between them, and easily tweak the underlying images, services, etc. you are booting with NixOS.

---

### DIY Labs

Various labs have engineered their own setups to meet their needs, and we don't want to say that the HWaaS can immediately replace any solution.

However, with the HWaaS, you may be buying into a greater test philosophy that can immediately make it easier to reproduce bugs, on real hardware, amongst teams.

**You will get, out of the box:**

- Remote KVM
- Remote Serial
- Remote USB OTG Boot
- Remote Auxiliary Device Control
- Shared hardware leases
- CI/CD Testing Library
- A Number of Examples
- Reproducibility with NixOS
- Easily Extend with Monitoring
- Memory Safe, Performant Infrastructure

If you fall into a subset of these categories, you may find a HWaaS setup to be
a valuable component of your CI/CD infrastructure.

Additionally, HWaaS components are easily sourceable, and the project is Apache 2.0 licensed, so the initial investment is reasonable.

Lastly, development is ongoing. If you or your team find a feature that you desire that is sufficiently general and
helpful for invested parties, we may look at upstreaming your changes.
